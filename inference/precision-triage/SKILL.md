# 精度问题定性与定位

先判断是否值得进入精度定位，再选择最小区分实验。乱码、空回答、输出变长、调用增多和得分下降都是症状；用户已经提供计算异常证据时，复核后直接进入定位，不重复要求从头跑检查。

## 入口定性

先读已有失败样本、原始响应、日志和最近改动，复用已确认的信息。缺失字段先从可访问记录补齐；只询问会改变下一步、又无法自行取得的信息。

运行入口实验前选一个能改变下一步的用例或现象，写清要区分的解释、固定输入、最小观测点和停止条件。预算依据故障频率、代价和用户约束。正式验收在运行前约定可信参考与判定规则；尚无规则时可以探索差异和波动，暂不作正式通过判定。

跨硬件或框架时，按 [跨平台对照准入](references/cross-platform-parity.md) 先用已有证据核对会影响当前问题的条件。把输入是否实际生效、观测位置和相关执行路径的核验并入首轮最小对照。先核验能否比较，再解释两端差异和同端波动。只在需要检验采集器或区分解释时追加对照样本；关键条件未对齐时，结论限于可观察的部署差异。

主动判断部署与生成参数是否能解释当前现象，而不只检查两端参数是否一致。结合实际模型、请求、部署方式和最近变更，从现象反查可能相关的参数与实现分支，读 [参数影响分析](references/parameter-effects.md)。这是判断方法，不是固定参数清单：只查有解释力的项；已有充分计算异常证据时不要为了走流程把所有参数重查一遍。

| 检查 | 最少证据 | 分流依据 |
|---|---|---|
| 外部原因 | 实际请求/模板/effort、输出限制与 stop、解析前后响应、服务异常 | 配置、服务或解析解释了现象，先沿该路径处理并重放验证。未找到外部原因不等于证明精度异常。 |
| 差异真实性 | 代表性坏例、必要条件对齐、同端重复波动与跨版本/实现对照 | 单次自由生成或评分变化先标原因未明。未复现或小样本未见差异不能证明无异常。 |
| 计算异常 | 相同 token prefix/固定张量下的可信参考、约定误差，或实际违反模型语义的证据 | 超出可解释误差、非有限值异常、漏执行必要 clamp、索引/写读错误等支持进入计算定位。高 EOS 概率、不同 logits 本身仍需控制条件。 |

输出一个或多个有证据的分流，注明适用症状与未解释部分：

- `EXTERNAL`：请求、服务、评测或解析原因已有证据，转对应工作流。
- `COMPUTE_EVIDENCE`：计算正确性异常已有证据，进入下面的定位。
- `UNRESOLVED`：列出下一项最小区分实验；不直接扩成全模型 dump、profiler 或全量跑批。
- `WITHIN_MEASURED_VARIATION`：本轮差异落在已测波动与检测能力内，注明样本和范围。

多个问题可以共存。预算耗尽时记录缺口与剩余假设；扩大实验要有新的区分目标，不能反复调整同一个开关。只读审阅不扩成重启、安装、切模型或共享服务负载测试；已有授权足够时继续执行，无须重复确认。

## 计算定位：按证据选步骤

1. **固定可比条件。** 保存输入/完整 token IDs、张量 shape/stride/layout/dtype、权重与量化、模板、采样、缓存、拓扑和实际加载版本。区分配置声明、运行证据与 unknown；当前状态不补写历史。重要条件不齐时只描述差异。
2. **验证采集与参考。** 用已知可控样本检验 hook/dump/checker 的层号、token 位置、mask、有效区域与误差计算；确认它能识别预设的局部差异。保存比较所需的实际数值快照，避免 buffer 原地复用污染结果。CPU、FP32 或另一后端不自动是真值。
3. **证明实际路径。** 追踪模型层 → 量化方法 → runner/分派 → kernel → 已加载 so/JIT。配置同名、kernel 同名、源码已修改都不能替代触发证据。先检查 clamp/scale/激活、mask/位置/索引、缓存写读及量化顺序是否保持模型语义，再解释浮点误差。
4. **寻找首个相关分歧。** 从阶段或模块边界二分，落到算子后比较中间值。报告绝对/相对误差的定义、异常坐标、有效元素和 NaN/Inf；logits 同时看候选间距、排名与 EOS。相似度高不能单独排除稀疏错误或 argmax 改变。
5. **验证单一假设。** 优先用保存的中间张量离线检验候选修复的数值方向，再在隔离实例改变一个变量。允许时同物理卡 A/B/A 回切。兼容性迫使联动改变参数时，记录整组变更与混杂，不能宣称已定位单个开关。
6. **分层验收。** 分开报告：目标路径已触发、数值/语义缺陷修复、原始用户现象改善、任务质量与必要性能。某层通过不替代其他层；缺触发/输出/参考或执行失败记 `INCONCLUSIVE`，有效违例记 `FAIL`，满足约定范围才记 `PASS`。

间歇问题记录异常 m/n 与输入/轮次，测试边界跟随当前假设。不要固定要求 1000 次，也不要把换卡、换权重、换量化得到的改善当成单因素证明。checker、原始参考与阈值保留；不通过裁剪异常值或放宽阈值制造通过。

## 按需读取

- 生成提前停止、错字、token 分叉、训练梯度或量化张量对照：读 [固定输入与比较方法](references/replay-and-comparison.md)，只使用相关段落。
- DCU/HCU、HIP/DTK、gfx936/gfx938 或私有后端分派：读 [DCU/HCU 专项参考](references/dcu-hcu.md)，含版本、参数对照与证据交接。工具缺失不妨碍静态审阅；不静默换用 CUDA 工具或安装环境。
- 需要历史案例帮助选择假设：读 [案例与结论边界](references/case-evidence.md)。历史经验提供线索，不替代当前运行证据。
- 交付记录可使用 [定位模板](assets/diagnosis-template.md)，按任务删减不适用字段。

## 最小交付

给出分流与证据、已执行/未执行项、可比条件、实验决策表、当前因果结论的强度，以及下一项最小补测。只做入口检查时交付入口结论即可，不强求整套文件。

如现有环境有 `experiment-manifest` 或 `regression-evidence`，可复用其清单/验收格式；它们不是本 skill 的执行依赖。纯性能问题可交给已有性能 skill；服务或硬件故障可转对应诊断工具，保留原始失败证据。
