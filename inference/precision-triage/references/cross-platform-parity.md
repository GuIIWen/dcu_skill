# 跨平台对照准入：NVIDIA 与 DCU 等场景

在进入数值定位前，先确认与当前问题相关的模型、输入和有效配置。已有证据先核对，只有实测能确认的项放进首轮最小对照。同一轮可以同时验证采集和测量差异；不要求先填完所有字段或建立通用工具。

参数对齐解决对照是否可比；[参数影响分析](parameter-effects.md) 进一步判断参数及所选实现是否能解释现象。两项按当前证据配合使用，不要求把所有参数都试一遍。

## 1. 先声明要比较什么

区分模型实现正确性、量化损失、框架差异、硬件相关数值差异，以及两个实际部署的总体质量。列出计划变量，其他重要差异作为混杂或 unknown。

例如 NVIDIA 跑原始 BF16、DCU 跑 Channel-FP8-W8A8，可以描述两套部署的结果差异；在未分离权重/量化变量前，不能把差异归因到 DCU 硬件或某个 kernel。

## 2. 两侧对照表

| 层次 | 核对内容 | 需要的运行证据 |
|---|---|---|
| 权重身份 | 模型 revision/来源、实际路径或挂载、分片索引与清单；是否同一 checkpoint 或可追溯转换 | 实际模型加载日志/路径与对应清单。模型名、目录名、文件大小或服务 models 响应不足以证明权重相同。 |
| 量化与权重变换 | 权重和激活 dtype、FP8/INT8 具体格式、channel/block/group 粒度、scale、校准与转换、加载时 transpose/repack/融合 | config 与实际量化类/加载分支对应；相同 FP8 标签不保证同一方案。改变存储布局需核验恢复后的逻辑值/scale 语义。 |
| config.json 有效语义 | 架构、层数、维度、MoE/router/top-k、hidden_act、swiglu_limit、norm epsilon、RoPE/位置与上下文配置 | 文件内容与哈希，加 config class 默认值、命令行 JSON override、环境变量和最终解析/使用值。必要字段不只检查文件字面值。 |
| tokenizer 与请求编码 | tokenizer 版本、词表/特殊 token、chat template、厂商 encoding 文件、thinking/effort、系统提示、工具格式 | 最终 prompt 和 token IDs、必要的 mask/位置；token 数相同不等于输入相同。 |
| generation_config.json 与请求 | BOS/EOS/PAD、stop/stop_token_ids、长度上限、temperature、top_p/top_k/min_p、penalty、seed、默认值继承与网关重写 | 原始请求、转换后请求和服务实际使用值。未传参数与显式设置分别记录。 |
| 服务有效运行模式 | 模型/计算 dtype、KV dtype/layout、prefill/decode/verify、spec 算法与宽度、prefix cache、chunk/context 配置、graph/eager、MoE/attention backend、TP/DP/EP | 实际进程命令、启动日志、相关 rank 与真实请求的入口/dispatch。参数名称不同但可语义对应；不支持的组合标不适用。 |
| 测量和评测 | 数据/题目、固定 prefix 或张量、客户端/agent/verifier、并发与请求顺序、超时、重试、预算与误差规则 | 同题/同输入可配对的原始记录。因服务失败未生成有效输出，不能当作数值失败。 |

只收集与当前差异有关的信息，优先复用已有模型 revision、制品摘要和清单。小配置可直接比较哈希与字段；是否需要读取全部巨大权重分片，按权重身份的疑点和 I/O 预算决定。抽样检查只能支持抽样范围，不能冒充完整权重一致性证明。

## 3. 参数对应与证据状态

每项填写：A 声明值、A 实际值、B 声明值、B 实际值、对应关系、证据路径及适用 run。

- **必须一致**：为了该实验成立所需的输入/模型语义，例如固定 prefix 实验中的实际 token IDs；具体清单由实验问题确定。
- **语义对应**：后端有不同参数名、支持方式或数据布局，但目标行为应等价，需有代码/运行证据。不要为了复制命令，强行使用目标不支持的参数。
- **计划变量**：本轮有意比较的差异，例如只切量化、runner 或版本。兼容性迫使多个参数联动时列为一组变量。
- **unknown / 不一致**：尚未查清或未对齐，记录影响与最小补查，不填推测默认值。

CUDA 与 HIP 的库/驱动、编译目标和部分实现天然不同，应记录其版本和实际选择；这些差异不要求字面一致。另一个硬件上的结果不自动构成正确性真值。

## 4. 对应到不同场景

- **输出变长、Agent 轮数或得分差异**：优先查真实权重、模板/effort、请求默认值、工具历史、服务限制与重试，随后才做固定输入数值比较。
- **提前 EOS、空正文、错字**：先核对特殊 token、stop、解析及输出上限，再固定 prefix 比较候选分布；核对 MoE clamp/scale 和 KV/attention 等共同语义。
- **MoE/量化 runner 回归**：保持同一逻辑权重与量化方案，确认 config 中的 swiglu_limit 等参数到实际 kernel 的传递和执行。不能用不同量化权重的结果单独归因 runner。
- **训练/反向梯度异常**：固定权重、输入、上游梯度、loss/AMP/scaler 与相关分布式状态，核对 TF32/累加精度的有效策略及各梯度路径。不同设备未必提供相同开关，按真实计算模式说明可比范围。

## 5. 准入结论

输出：`适合目标对照 / 仅能描述部署差异 / 证据不足`，附理由。未准入不妨碍继续查权重或配置本身，也不抹掉已独立证实的计算缺陷；只限制该跨平台对照所能支持的归因。

## 首轮最小对照

1. 选一个有区分力的固定输入，优先用已有坏例。写明比较哪一位置或张量、需要怎样的重复，以及本轮结果如何影响下一步。若要正式验收，提前写明可信参考、判定规则及来源；另一端的结果不会自动成为真值。
2. 用两端当前可用的入口采集。先核验实际采用的输入、观测位置或有效区域、相关执行阶段；例如固定前缀重放可能把原来的 decode 变成 prefill，截断的候选列表只支持可见范围。核验通过的样本可直接进入本轮比较，无需重跑一套独立预检。
3. 记录同端重复与跨端差异。输入或观测未核实时补最小证据；差异落在已测波动内时注明适用范围；差异可重复且条件支持时再定位阶段或算子。未约定规则的探索结果记录差异，不事后定义正式合格线。
