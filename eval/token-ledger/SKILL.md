# 可追溯 token 账本

从能定位请求事件的记录开始。先整理逐请求数据，再按用户关心的运行、会话或批次汇总。

1. 从源数据确认字段口径和请求边界，保留来源和原始记录位置。区分重复记录、流式增量、累计快照与真实重试；不要按文本相似度去重。重试独立计入，失败请求有可信计数也计入。
2. 缺失保留未知，明确的零才计零。总量和子项不能重复相加；缓存命中率用同时有输入量和读缓存量的请求计算，附适用分母和覆盖数。能对账时以源计数复核并解释差异。
3. 交付逐请求记录、汇总及覆盖缺口。没有完整请求或任务清单时，只报告日志覆盖范围。比较时明确群组、配对依据和分母；条件不齐时可以描述差异，归因留待确认。

可用现有工具处理；需要标准字段、计算口径或批量汇总脚本时查阅[账本约定](references/ledger-contract.md)。
